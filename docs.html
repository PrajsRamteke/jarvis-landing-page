Overview

Jarvis is a terminal-native AI coding agent — the Harness Agent that lives in your terminal. Talk to it, and it reads/writes files, runs shell commands, searches code, manages git, controls macOS apps, OCRs images, browses the web, and gets work done right where your code lives.

No web UI, no daemon. Just jarvis in your project folder. Built on Python 3.10+ with the Anthropic API (and OpenRouter, OpenCode, OpenCode Zen, and custom providers).

Install

One-command install (recommended)

curl -fsSL https://raw.githubusercontent.com/PrajsRamteke/harness-agent/main/scripts/install | bash
source ~/.zshrc

After install, open a new terminal, go to any project, and run jarvis.

Troubleshooting: If jarvis: command not found, add ~/.local/bin to your PATH: export PATH="$HOME/.local/bin:$PATH"

Development setup

git clone https://github.com/PrajsRamteke/harness-agent.git
cd harness-agent
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
jarvis --help

Run the agent

jarvis                     # TUI mode (default)
java agent.py              # same as jarvis
python agent.py --legacy   # Rich REPL mode

TUI Interface

Jarvis provides an interactive terminal user interface (TUI) built with Textual. Running jarvis from your project folder starts the TUI.

Layout

The TUI is composed of several panels and zones:

  • Conversation area — scrollable chat with markdown-rendered messages, syntax-highlighted code blocks, and collapsible tool outputs.
  • Prompt input — multi-line text area at the bottom. Type your message and press Enter to send. Use / commands.
  • Status bar — bottom strip showing project path, active provider, model, agent, token count, and live indicators.
  • Thinking panel — live view of the model's reasoning process (for models that support extended thinking).
  • Tool viewer — press F3 to scroll through recent tool outputs.

File references

Reference files in your messages using @. This does a fuzzy file search in the current working directory.

How is auth handled in @jarvis/auth/client.py?

The content of the file is added to the conversation automatically.

Bash commands

Start a message with ! to run a shell command. The output is added to the conversation as context. 

! ls -la

Images & attachments

Drag and drop images into the terminal to add them to the prompt. Jarvis uses OCR to read text from images. You can also paste images from the clipboard.

Web Remote

Jarvis includes a mobile-friendly web UI for browser-based remote control. Enable it with the --web flag.

jarvis --web
# or with custom port:
jarvis --web 9090

Once active, a QR code is shown in the terminal. Scan it with your phone or open the URL in any browser on the same network.

Features

  • Mobile-friendly — responsive UI works on phones and tablets
  • Real-time streaming — see assistant responses as they arrive
  • Session management — switch sessions, view history
  • File browsing — view project files
  • Model & provider selection — change settings on the fly
  • Console multiplexing — TUI and web share the same session seamlessly
Network: The web UI binds to 0.0.0.0:PORT. For security, avoid exposing it to untrusted networks.

Context Tools

Jarvis's connected context pack replaces 5-20 separate file reads with a single call. These are the agent's superpower for codebase understanding.

resolve_context

Give it a task description and get all related files at once — targets, imports, importers, tests, types, and configs. The repo graph builds automatically.

resolve_context(task="Fix login bug in JWT token refresh")
# Returns: jwt.py, auth.py, middleware.py, test_auth.py, types.py, config.py — all in one shot

read_bundle

Batch-read 2-20 specific paths with parallel I/O. Budget-aware: splits the output cap across files and returns as much as fits.

read_bundle(["src/auth.py", "src/middleware.py", "src/types.py"])
# Returns: all three files with content, no wasted round-trips

Savings

Without context tools: 10+ read_file calls, ~5-10 seconds, ~50K tokens overhead. With context tools: 1-2 calls, ~1 second, minimal overhead.

Tool Repair

Jarvis automatically validates and repairs model-generated tool inputs. When the model sends malformed arguments, the repair layer fixes them before execution — so you don't see errors.

Repair pipeline (14 stages)

  1. Parse stringified args — whole input sent as a JSON string → dict
  2. Unwrap envelopes — {"arguments": {...}} → inner dict
  3. Fix field aliases — file_path → path, old → old_str
  4. Strip null values — remove null from optional fields
  5. Strip extra fields — remove fields not in the schema
  6. Parse stringified arrays — "['a','b']" → ["a", "b"]
  7. Parse stringified objects — "{...}" → {...}
  8. Fix wrong containers — unwrap [{...}] → {...}
  9. Clean paths — ["path"] → "path"
  10. Fix string numbers — "10" → 10
  11. Fix boolean strings — "true" → True
  12. Coerce to string — list of lines joined, dict serialized
  13. Fix markdown paths — [file.md](...) → file.md
  14. Repair nested arrays — fix each item of multi_edit.edits, ask_user_question.questions

Each fixer is idempotent — correct inputs pass through with zero changes. The UI shows a small ⚒ indicator when repairs were applied.

Plan Mode

Plan mode restricts Jarvis to read-only operations. It can analyze, suggest, and explain — but cannot write files, run shell commands, or make changes. Use it when you want a plan before execution.

/plan on          # Enter plan mode
/plan off         # Exit plan mode

In plan mode, only these tools are available:

  • File reading (read_file, read_bundle, read_document)
  • Search & listing (search_code, glob_files, rank_files, list_dir, fast_find)
  • Context tools (resolve_context)
  • Git (git_status, git_diff, git_log)
  • Internet & web
  • ask_user_question
  • exit_plan_mode — used when you approve the plan to automatically switch back to build mode
Tip: Describe what you want built. The agent will analyze the codebase, explain its approach, and wait for your approval before making changes.

Configuration

Jarvis uses a unified ~/.config/harness-agent/settings.json file for all preferences. Per-project overrides go in .harness/settings.json in your project root.

Global settings

{
  "model": "sonnet-4-6",
  "theme": "red",
  "think": {
    "mode": true,
    "effort": "medium"
  },
  "skills": { "global": false },
  "mcp":    { "global": false },
  "trace":  { "on": true }
}

Per-project config

Place a .harness/settings.json in your project root. These settings merge with (and override) the global config:

// .harness/settings.json
{
  "model": "claude-sonnet-4-20250514",
  "theme": "cyberpunk",
  "skills": { "global": true }
}

Using the settings modal

Type /settings in the TUI to open the settings manager. Browse and toggle all options without editing files by hand.

Agents

Agents are reusable markdown files with YAML frontmatter that add a system-prompt addon when activated. They replace the legacy mode system and let you define specialized personas.

Creating an agent

# .harness/agents/reviewer.md
---
name: reviewer
description: Code review specialist — thorough, security-aware
icon: "🔍"
color: "#58a6ff"
---

You are a code review specialist. Focus on:
1. Security vulnerabilities (injection, XSS, auth bypass)
2. Performance bottlenecks (N+1 queries, memory leaks)
3. Edge cases (empty states, concurrent access)
4. Code style & maintainability

Always provide specific line-level feedback with code suggestions.

Skills

Skills are instruction packs (SKILL.md files) that the LLM auto-loads when its description matches the task. Unlike agents, skills are automatically invoked — the model decides when to load them.

Creating a skill

# .skills/security-review/SKILL.md
---
name: security-review
description: Audit code for OWASP Top 10 vulnerabilities, injected dependencies, and hardcoded secrets. Use whenever you see auth code, database queries, or user input handling.
compatibility: "Anthropic, OpenRouter, OpenCode"
---

## Security Review Checklist

1. Check for SQL injection — raw string interpolation in queries
2. Check for XSS — unescaped user input in templates/HTML
3. Check for hardcoded secrets — API keys, tokens, passwords
4. Check authentication — weak password rules, missing MFA
5. Check authorization — missing role checks, IDOR patterns
6. Check dependency — known vulnerable versions
7. Check output encoding — Content-Type, CSP headers

MCP Support

Jarvis supports the Model Context Protocol (MCP) for connecting external tools and data sources. MCP servers add dynamically discovered tools that the agent can use.

Quick start

Type /mcp in the TUI to open the MCP manager. Here you can:

  • Connect to MCP servers defined in .mcp.json
  • Toggle global scope — press g to include MCP servers from Claude Code, OpenCode, Cursor
  • View available tools from connected servers
  • Disconnect servers as needed

Global MCP — import from other tools

Jarvis can adopt MCP servers that were configured for Claude Code, OpenCode, or Cursor. Toggle global scope with a single key press (g) in the MCP manager.

Global MCP sources (loaded when global scope is on):

Source Config file
Claude Code ~/.claude/settings.json (mcpServers)
OpenCode ~/.config/opencode/mcp.json
Cursor ~/.cursor/mcp.json
Legacy Claude ~/.config/claude/mcp.json
One press to rule them all: Press g in the /mcp modal to instantly import ALL MCP servers from every supported tool. No manual copying needed.

Project scope

By default, only the project's .mcp.json is loaded (project scope). Enable global scope with /mcp → press g to include MCP servers from global config files.

Privacy: Global MCP servers from ~/.cursor, ~/.claude, ~/.config/opencode are only loaded when you explicitly toggle global scope on.

Memory

Jarvis remembers facts about you across sessions using persistent JSON storage. It proactively saves information it learns without asking.

/memory       # View all stored facts (modal)
/memories     # Same as /memory

How it works

  • The agent calls memory_save when it learns something about you
  • Facts are stored in ~/.config/harness-agent/memory.json
  • Facts are injected into the system prompt on every session start
  • Deduplication — duplicate facts are silently skipped
  • Thread-safe — concurrent tool calls don't race on read/write

Storage format

{
  "facts": [
    { "id": 1, "text": "name: Prajwal", "ts": 1710000000 },
    { "id": 2, "text": "preferred editor: VS Code", "ts": 1710000100 }
  ],
  "next_id": 3
}

Lessons

Lessons are the agent's self-learning system. It stores patterns → solutions so future similar tasks are faster with fewer tool calls.

/lesson "git rebase"     # Search lessons by topic
/lesson                  # Open lesson manager
/lessons                 # Same as /lesson

How it works

  • Agent calls lesson_save when it discovers a reusable pattern
  • Up to 8 relevant lessons are injected into the system prompt each turn
  • Lessons are tagged with topics for searchability
  • Max 200 entries; oldest low-hit lessons are pruned
  • Each lesson tracks hit count for relevance scoring

Storage

Lessons are stored at ~/.config/harness-agent/lessons.json.

Project Context

Jarvis automatically detects project context files and loads them as reference. This helps the agent understand your project's structure, patterns, and conventions.

Supported files

Detected in priority order (first found wins):

  1. AGENTS.md
  2. AGENT.md
  3. CLAUDE.md
  4. JARVIS.md

Only the path is stored at startup; content is loaded on demand via read_file(). The status bar shows which context file was found.

Tip: Commit your project's AGENTS.md file to Git. This helps Jarvis understand the project structure and coding patterns used.

Pinned Context — Always-On Prompt

Pinned context is text that's always injected into the system prompt — it goes with every single prompt you send. Use it for instructions you want Jarvis to follow in every session, without having to repeat them.

Always on: Unlike a one-shot instruction, pinned context is injected before every message. It's always there — you don't need to remind the model each time.

Commands

Command Action
/pin Open pin manager
/pin set <text> Set pinned context (replaces existing)
/pin clear Clear pinned context
/pin toggle Enable/disable injection
/pin on Enable pinned context
/pin off Disable pinned context

Use cases

Persistence

Pinned context is stored at ~/.config/harness-agent/pinned.txt. It persists across sessions and restarts. Toggle injection on/off with /pin toggle without losing your pinned text.

No Project Jail

Unlike most AI coding agents that lock you inside the current working directory, Jarvis has no project jail. It can read, write, and list files anywhere on your machine — the project root is just a default, not a cage.

Full filesystem access: You can reference files outside the project root with allow_outside_project=true. Tools like read_file, write_file, edit_file, list_dir, search_code, glob_files, fast_find, and read_document all support working anywhere on your Mac.

How it works

Tool Outside-project access
read_file Use force=true for any file on disk
write_file Use allow_outside_project=true
edit_file Use allow_outside_project=true
list_dir Use allow_outside_project=true for any directory
fast_find Spotlight search across entire Mac — path=~/Desktop, path=/Applications, or whole system
read_document Use force=true for PDFs, images, spreadsheets anywhere
search_code Use allow_outside_project=true to search any folder

Use cases

  • Read configs from ~/.config/ or ~/.ssh/
  • Inspect logs in /var/log/ or ~/Library/Logs/
  • Edit dotfiles in your home directory
  • Search code in sibling projects
  • Read install receipts, plists, or system files
  • Glob files across ~/Downloads, ~/Desktop, ~/Documents
Safety first: Outside-project access requires explicit opt-in per call (force / allow_outside_project). Jarvis never reads outside the project without being told to.

Troubleshooting

Jarvis won't start

Most common cause: Python version. macOS ships with Python 3.8 or older. Install Python 3.10+: 

brew install python@3.11

"command not found: jarvis"

Your shell can't find the binary. Add it to PATH:

export PATH="$HOME/.local/bin:$PATH"
# Add to ~/.zshrc to make permanent

Authentication issues

  • Check ANTHROPIC_API_KEY is set: echo $ANTHROPIC_API_KEY
  • Run /login to re-authenticate with OAuth
  • Run /key to enter a new API key
  • Check HARNESS_PROVIDER env var if pinned to wrong provider

Model not available

  • Run /models to see available models
  • Run /provider to switch providers
  • Check your account has access to the model tier

macOS accessibility denied

If Jarvis can't read the UI or click elements:

  1. Open System Settings → Privacy & Security → Accessibility
  2. Add your terminal app (Terminal, iTerm2, Warp, etc.)
  3. Restart your terminal

Logs

Jarvis writes logs to the console during operation. For debugging, run with more verbose output by checking the HARNESS_* debug environment variables.

Get help

  • Type /help in the TUI to see all commands
  • Check the GitHub repo for issues
  • File a bug report with session export (/export)
